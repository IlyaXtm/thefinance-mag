# Verification and design audit — 2026-08-20

Handoff baseline plus the design audit, run against a production build
(`next build && next start`), measured rather than eyeballed.

**Data source: mock, not WordPress.** The session's network policy blocks
`wp.thefinance.ir` and `thefinance.ir` (gateway answers 403 to CONNECT), so
nothing here was verified against real content. The mock runs the same content
pipeline as the real API — `addHeadingIds(sanitizeArticleHtml(...))`, identical
return shapes — so structure, layout, typography, semantics and the SEO
mapping are all exercised. What is *not* covered is anything that depends on
the actual archive: real slugs, the 41-minute article's heading count, whether
Rank Math's payload matches `MagSeo`, and the `countArticles` timing. Those
still need one pass on a machine that can reach the CMS.

Coverage: 9 routes × 3 viewports (1280 / 1024 / 390) × 3 themes (`v1`,
`v2-dark`, `v2-light`) = 81 combinations, instrumented in Chromium.

---

## Blocking — found and fixed

### 1. Search was unreachable from every entry point

`<form action="/search">` in three places. Next.js applies `basePath` to
`next/link` and the router but **not** to a native form action, so every search
posted to `thefinance.ir/search` — the main site — instead of the magazine.
Confirmed live: submitting from `/mag` landed on a 404.

Fixed with `magPath()` in `lib/site.ts`; every native action goes through it.

### 2. Pagination pointed at routes that do not exist

`Pagination` derived hrefs from a `basePath` string, special-casing `/archive`
and falling through to `` `${base}/page/N` `` for everything else. Measured:

| link emitted | status |
|---|---|
| `/mag/page/2` | 200 |
| `/mag/market/crypto/page/2` | **404** |
| `/mag/author/<slug>/page/2` | **404** |
| `/mag/search/page/2` | **404** |

Crawlers follow those. Worse, the market and author pages fetched
`{ page: 1 }` hardcoded while still rendering pagination, so **every article
past the ninth in a market or by an author had no route at all**. And the
`/archive` branch rebuilt the URL from scratch, dropping the `type` it was
paginating: `/archive?type=education` paged to `/archive?page=2`, silently
switching the reader back to everything.

Fixed by having the route build its own hrefs (`pagePathHref` /
`pageQueryHref`), since the route is what knows its URL shape. Market, author
and search paginate by query string like the archive; `type` and `q` travel
with the page number.

### 3. The logo 400'd in the header and footer on every page

`next/image` prefixes the optimizer *route* with basePath but not the `url`
parameter, so `/mag/_next/image?url=%2Flogo.png` resolved against the server
root and returned `400 The requested resource isn't a valid image`. Both marks
were invisible site-wide.

Fixed by importing the file as a static asset
(`src/shared/assets/logo.png`), which carries the correct path. Verified: 200,
`image/png`, `naturalWidth` 32 on every page.

### 4. The author page had no `<h1>`

The name rendered only as a link inside `AuthorBox` — pointing at the page it
was already on — and the page's first heading was the visually-hidden `<h2>`.
Every other archive gets this right; the author page was the exception.

`AuthorBox` now takes `isCurrentPage` and renders the name as the `h1` there,
which also removes the self-link tab stop the breadcrumb trail already avoids.

## Should fix — found and fixed

**In-body blocks rendered as unstyled divs.** `thefinance/callout` and
`thefinance/disclaimer` arrive in the body HTML and had no styling at all: the
callout was indistinguishable from surrounding prose, and the disclaimer —
legal protection, not editorial voice — read as the article's closing sentence.
Styled by attribute selector, as the rest of `.article-body` is. No heading
element introduced, so the ToC outline is untouched.

**No `pre`/`code` overflow handling.** Tables and images were handled; code was
not, and a long unbroken token is the one thing left that can blow out the
700px column. Now scrolls in its own box, `direction: ltr` isolated.

**The newsletter and comment forms weren't forms.** Both were `type="button"`
with an `onClick`, so pressing Enter did nothing — the way most people submit a
single-field form. Both are real `<form>` elements now.

## Verified passing

Measured, not assumed.

**Contrast.** Every ratio claimed in `tokens.css` recomputed from the hex
values, alpha-composited onto the actual surface:

| token | v1 | v2-dark | v2-light |
|---|---|---|---|
| `text-primary` on surface | 19.49 | 18.97 | 18.71 |
| `text-secondary` on surface | 13.15 | 13.36 | 9.87 |
| `text-muted` on surface-raised | 7.26 | 7.11 | **6.43** |
| `border-interactive` on surface | 3.95 | 4.30 | 4.23 |
| `border-interactive` on surface-hover | 3.41 | 3.58 | 3.55 |
| `focus-ring` on surface | 6.84 | 6.95 | **6.12** |
| `focus-ring` on surface-raised | 6.43 | 6.29 | 5.55 |
| `accent-contrast` on accent | 6.67 | 6.61 | 6.12 |

All body text clears 4.5:1, all focus indicators and interactive boundaries
clear 3:1 on every surface. **The documented `v2-light` focus defect is fixed**
— the ring computes to `rgb(26, 95, 191)`, the darker accent at 6.12 against
white, not the 2.85 dark-theme blue.

**Keyboard focus.** Tabbed 39 stops through a full article page in `v2-light`:
39/39 carried a `2px solid` outline at `3px` offset. Zero lost rings.

**Article layout at 1280.** Container `x=100 w=1080` — centred, not pinned.
Body column exactly **700px**. ToC at `x=100…360` — the left edge, inline-end
in RTL. ToC list `max-height: 772px` with `overflow-y: auto`, so it scrolls
internally rather than defeating its own sticky behaviour.

**Table of contents.** All 4 hrefs resolve to real ids; body ids and ToC hrefs
both come from `headingId()` and match exactly. Clicking entry 3 landed the
heading at `top: 96px` — exactly its `scroll-margin-top`, clearing the header.
Scroll-spy traced at 300px intervals tracks the reader correctly; nothing is
highlighted before the first heading, which is right.

**Typography.** Body 18px desktop / 17px mobile, line-height 34.2px and 32.3px
= **1.9** exactly. `text-align: start` everywhere. Weight 400. IRANYekanX
self-hosted, no external font request. Zero `font-style: italic` and zero
`text-align: justify` across all 81 combinations.

**RTL.** Zero physical `left`/`right` properties, zero `scrollLeft`, zero
`localStorage`. Chevrons point left in breadcrumbs, pagination and «آرشیو ←».
Latin fragments measured character-by-character in visual order: «تحلیل
فاندامنتال (Fundamental Analysis) چیست؟» renders as *[Persian] ( [Latin LTR] )
[Persian]* — correct, no scrambling. See the note below on how that happens.

**Layout.** No horizontal overflow anywhere — `scrollWidth == clientWidth` on
all 81 combinations. Footer sticks on short pages. Page padding 20/100, section
spacing 60/96. Persian digits on dates, reading time and counts.

**Semantics.** Exactly one `<h1>` per page (after the author fix), no heading
level skips, cards are `<article>` with one link and no duplicate `aria-label`,
filters and pagination are real `<a href>`, every input labelled.

**SEO.** Canonicals per-article on `thefinance.ir`, never the CMS host. `og:title`
differs per article. JSON-LD parses; `dateModified` appears only where a real
revision exists. Sitemap: 16 URLs, **zero** `wp.thefinance.ir`. `/search` is
`noindex, follow`. Zero occurrences of the CMS host in any rendered page.

**Brand.** No view/comment/reaction counts, no trending section, no urgency
badges or countdowns, no live price data, no follower counts or superlatives,
no profit or scarcity language. Newsletter copy unchanged. Standing disclaimer
present in the footer.

**Deliberate items confirmed intact and not touched:** one image on the index
(hero only — the two others on the page are the header and footer logo marks),
no article appearing twice, `housing` absent from Topics, education section
unnumbered, reports empty, search `noindex`, avatars as initials, no
`aria-label` on card links.

## Resolved by the docs added 2026-08-20

The `docs/` archive imported after this audit answered one of its open
questions and turned the rest of it into a defect.

**`اخبار` is in scope.** The audit flagged `CONTENT_TYPES` shipping
`{ slug: 'news', name: 'اخبار' }` against CLAUDE.md, which lists it as
deliberately excluded pending the Khabarchi boundary. `changelog.md` records
the decision that closed it: "**`اخبار` added as a fourth content type.** An
RSS automation publishes about two items a day and they're meant to be
indexed." So the code is right and **CLAUDE.md's exclusion line is the stale
one** — worth correcting there, since it is the document agents read first.

**The NewsArticle half was a real gap, now fixed.** The same changelog entry
records "News gets `NewsArticle` schema rather than `Article` — publication
date is the signal for translated news, revision date for evergreen
education." That was never implemented: `articleJsonLd` emitted `Article`
unconditionally, and the comment above it still read "if `اخبار` ever enters
Mag" — written as though it hadn't. Three documents said NewsArticle; the code
said Article for everything.

`articleJsonLd` now emits `NewsArticle` when `contentType.slug === 'news'` and
`Article` otherwise. Verified against a real render:

| article | `@type` | `dateModified` |
|---|---|---|
| `fed-holds-rates-august` (اخبار) | `NewsArticle` | none |
| `bank-half-year-financials` (گزارش) | `Article` | none |
| `fundamental-analysis` (آموزش) | `Article` | 2026-08-18 |

**The mock had no `news` fixture**, which is why the gap survived: the branch
the changelog describes as shipping twice a day could not be exercised at all
locally. Added one — a translated news item with no revision, so publication
date is its only freshness signal, which is the case NewsArticle exists for.
The mock's own header warns about exactly this failure mode ("a mock that skips
the transforms isn't testing the component, it's testing a different
component"); a mock missing a whole content type is the same class of gap.

## Open — not changed, needs a decision

**`npm run lint` cannot run.** No `.eslintrc*` or `eslint.config.*` exists, so
`next lint` drops into its interactive setup prompt. `next.config.ts` sets
`eslint: { ignoreDuringBuilds: false }`, which is a no-op with no config —
linting has never actually run. Choosing Strict vs Base is a project decision.

**`ORGANIZATION.logo` points at `https://thefinance.ir/logo.png`** (site root,
not `/mag`). Every JSON-LD block on every page references it as the publisher
logo. Unverifiable from here; worth one `curl` on a machine that can reach it.

**`public/logo.png` is now unreferenced** by the app. Left in place rather than
deleted — it serves at `/mag/logo.png` and an external reference can't be ruled
out from here.

**Mock cover images 404.** `mag.mock.ts` points at `/mock/covers/*.jpg` and
`/mock/authors/*.jpg`, none of which exist in `public/`. Every mock run shows
broken image boxes, which undercuts the mock's stated job of making UI states
testable. Fixture assets, not a product defect.

**The table of contents is in the DOM four times.** The article page mounts
`<TableOfContents>` twice — once in a `lg:hidden` wrapper for the in-flow
mobile position, once in the `hidden lg:block` aside — and the component
itself also renders both a desktop `<nav>` and a mobile `<details>`. The
responsive switch happens twice, so each anchor appears 4×, with only one
visible at a time. Correct on screen and in the a11y tree (`display: none`
subtrees are excluded), but it also runs a second IntersectionObserver over
every heading. On the 41-minute article that is real duplicated scroll work.
Left alone: the fix means restructuring a component that works.

**`/mag/page/[n]` is orphaned.** Nothing links to it — the index has no
pagination and the archive uses its own — and it isn't in the sitemap. Harmless
but reachable only by typing the URL.

**Body column is 524px at exactly 1024px**, not 700px, because the ToC's 260px
plus the gap comes out of the same row at the `lg` breakpoint. Roughly 52
characters per line rather than the target 70–73. Not a defect at 1280 (700px,
correct) or on mobile (full width), but 1024 is the one width where the reading
measure is off. Fixing it means moving the ToC breakpoint to `xl`.

**Latin fragments rely on browser bidi bracket-pairing.** CLAUDE.md prescribes
wrapping every Latin fragment in `<span dir="ltr" style="unicode-bidi:isolate">`.
No title anywhere does this — the `.ltr` utility is used only for the search
query and inside body HTML. Measurement shows Chromium resolves the bracketed
cases correctly via UAX#9 BD16, so there is no visible defect today. But the
guarantee is the engine's, not the code's, and an unbracketed fragment in a
different position would not be covered by it.

**`countArticles` unmeasured.** It walks the connection in pages of 100, capped
at 20 hops, cached an hour per filter set. With 32 articles that is a single
hop and not a hot spot. It becomes one somewhere past a few hundred articles,
or if the cache is cold on every regeneration. Needs measuring against the real
endpoint before optimising — the handoff's suspicion is reasonable but
unconfirmed.

**Stale ISR cache survives a rebuild.** `next start` served the previous
build's `/mag` HTML after a rebuild until `.next` was removed. Standard Next
behaviour, but the deployment needs to not ship a stale `.next/cache`, or the
first readers get the old page.

## Outside this repo — unchanged, still outstanding

Carried forward from the handoff; none is actionable here.

- **Comment moderation is OFF** (`comment_moderation = 0`). The frontend only
  renders approved comments so nothing leaks, but WordPress is publishing
  without review, which is the opposite of the decision made.
- **`robots.txt` on the main site** has three defects, in `thefinance-front`:
  `Disallow: *.xml$` blocks the sitemap declared in the same file (costing
  indexation today), `Disallow: *.thefinance.ir/` is inert because robots.txt
  matches paths not hosts, and `/map/wp-content/plugins/` is a typo for `/mag/`.
- **SPF and DMARC are not published** for `thefinance.ir`. Newsletter
  confirmation mail will land in spam.
