# Design audit — second pass

Follows `audit-2026-08-20.md`. Nothing already fixed there is re-reported.

**Data source: still mock.** `wp.thefinance.ir` and `thefinance.ir` are both
blocked by this container's network policy — the proxy answers 403 to CONNECT.
`/mag/health` says `"source":"mock"`. **Section 1 of the brief (real content
stress cases) was therefore not run**, and nothing below is a claim about real
archive content.

What was done instead: the adversarial fixtures of section 3 were built to the
shapes Phase 0 measured — a 41-minute read with 24 headings and
WordPress-authored HTML, a 3-line title, a market-less article, a bio-less
author, one-H2 and zero-H2 articles, a percent-encoded Persian slug. They are
**synthetic**. They prove the components survive the shape. They do not prove
production content is fine.

Coverage: 14 routes × 3 viewports × 3 themes = 126 combinations for the
structural sweep, plus interaction, theme-switch and print passes.

## Blocking — found and fixed

### 1. One long token made the whole article page scroll sideways on mobile

A single unbreakable string — a wallet address, a long ticker, a bare URL — is
laid out as one atomic inline box. The content column's overflow is `visible`,
so it neither clipped nor scrolled: it painted outside and dragged the page's
scroll width with it.

Measured on a 390px viewport, from one 72-character token:

| | before | after |
|---|---|---|
| `document.scrollWidth` | **692px** | 390px |
| `clientWidth` | 390px | 390px |

Tables and `<pre>` were already fine — both scroll internally, verified at
`rectW=350` with the content at 421px and 784px respectively. Running prose has
nowhere to scroll, so it has to wrap. Fixed with `overflow-wrap: break-word` on
`.article-body` and `overflow-wrap: anywhere` on inline `code`.

The first pass reported "no horizontal overflow on all 81 combinations" and
that was true of what it tested — the mock article has no table, no `pre` and
no long token. This is the class of defect only adversarial content reaches.

### 2. Printing an article produced a blank sheet

Nothing was defined for print — no `@media print` rule existed anywhere.
Browsers drop background colours when printing but keep text colours, so the
dark theme printed its foreground onto white paper:

| element | colour | on white paper |
|---|---|---|
| headings | `#ffffff` | **1.00:1** — invisible |
| body | `#d4d4d4` | **1.48:1** — illegible |
| muted | `#a3a3a3` | 2.52:1 — illegible |
| links | `#4d9afe` | 2.85:1 |

People print financial explainers; a 41-minute technical-analysis piece is
exactly what gets printed and marked up.

Fixed with one `@media print` block. Because the tokens are two-tier,
redefining the semantic roles for print re-colours every component at once and
no component needs to know print exists. Verified in all three themes: body and
headings `rgb(0,0,0)` on `rgb(255,255,255)`; header, footer, ToC, breadcrumbs,
newsletter and comment form all `display: none`; **the standing disclaimer
still prints** — it is legal protection, not decoration; tables and `pre` switch
from scrolling to wrapping; headings get `break-after: avoid` and figures get
`break-inside: avoid`. Body links print their href, isolated LTR so the URL
doesn't disturb the surrounding Persian.

### 3. Out-of-range pages answered 200 with page-1 content

`/mag/page/999`, `/mag/archive?page=999`, `/mag/market/crypto?page=999` and
`/mag/author/<slug>?page=999` all returned 200. Two separate causes:

**The mock clamped the page number.** `paginate()` did
`Math.min(Math.max(1, page), totalPages)`, so an out-of-range page silently
became page 1 and returned a full set of items. The real API doesn't clamp — it
returns whatever the cursor walk finds, i.e. nothing. So the
`items.length === 0 → notFound()` guard in `/page/[n]` **could never fire
locally**, and dev and production disagreed about the status code. Removed the
clamp; the mock now mirrors the real API.

**The archive had no out-of-range handling and no empty state at all.** It
mapped `articles.items` straight into rows, so with real data
`?page=999` renders a heading, a filter bar and nothing else at 200 — a thin
page in the index, against a product whose first priority is SEO. The market
and author archives had an empty state but would have used it to claim
"nothing published yet", which is false when the reader merely asked for a page
past the end.

Added `isPageBeyondEnd(page, count)` in `lib/nav.ts` — `page > 1 && count === 0`
— and applied it to the archive, market and author routes. Page 1 empty still
means "nothing here" and keeps its empty state; past the end is a URL that does
not exist and 404s. The archive also gained the empty state it never had.

Verified after the fix:

| URL | before | after |
|---|---|---|
| `/mag/page/2`, `/mag/page/999` | 200 | **404** |
| `/mag/archive?page=2`, `?page=999` | 200 | **404** |
| `/mag/market/crypto?page=999` | 200 | **404** |
| `/mag/author/maryam-rezaei?page=999` | 200 | **404** |
| `/mag/archive`, `?type=report`, `?type=nonsense` | 200 | 200 |
| `/mag/market/housing`, `/mag/author/no-bio-author` | 200 | 200 |

## Should fix — found and fixed

**ESLint had never run.** Confirmed as reported: no config existed, so
`ignoreDuringBuilds: false` was a no-op and `next lint` dropped into its setup
prompt. Added `eslint.config.mjs` on `next/core-web-vitals` +
`next/typescript` — the rules that catch a raw `<img>` on the LCP path are
exactly the ones worth failing a build over. `npm run lint` now runs the ESLint
CLI directly, since `next lint` is removed in Next 16.

It found two things, both now clean:
- `postcss.config.mjs` exported an anonymous object — rewritten to a named one.
- `_submission` flagged as unused. The underscore is this codebase's existing
  marker for a parameter kept to match the real API's signature, so the rule
  now honours `^_` rather than the parameter being renamed to satisfy it.

**The mock's `housing` market contradicted itself.** The fixture comment says
`count: 0` is deliberate, "matching the real archive", so the hide-empty-markets
rule stays exercised. But `tehran-housing-spring-1405` still pointed at
`MARKETS.housing` — so the filter bar hid housing while `/market/housing`
rendered an article, and the empty archive was unreachable. That article is now
market-less, which also supplies the case Phase 0 says is the majority of the
real archive (18 of 32 have no market). `/mag/market/housing` now shows a real
empty state: «۰ مطلب», «هنوز مطلبی در مسکن منتشر نشده» and a route onward.

## Verified passing

**Adversarial content.** All handled correctly:

| case | result |
|---|---|
| one H2 | ToC omitted entirely — not a one-row list |
| zero H2s | ToC omitted; no gap left behind |
| no featured image | hero block absent, layout closes cleanly |
| no market | chip absent, meta row closes cleanly |
| author with no bio | renders name, role, count; no empty block |
| market with exactly one article | no pagination, no empty state |
| `/mag/market/housing` (zero articles) | «۰ مطلب» + empty state + route onward |
| search: no results | «نتیجه‌ای برای «…» پیدا نشد» + market links + latest |
| search: empty and whitespace-only | «عبارتی برای جستجو وارد کنید» — a prompt, not an error |
| search: Latin query `P/E` | handled, `noindex, follow` |
| `?type=nonsense` | ignored, canonical `/mag/archive` — no soft duplicate |
| percent-encoded Persian slug | **200** |

The percent-encoded slug resolves because the route param arrives decoded and
the lookup matches. The **re-encode** on the way to WordPress lives in
`mag.api.ts` and cannot be exercised without the CMS.

**Long article (24 headings, 41 minutes).** ToC list capped at `max-height:
772px` with `overflow-y: auto`, content 939px — it scrolls internally rather
than defeating the sticky container. Body column 700px. Nested lists, tables,
blockquotes, inline figures and `pre` all render inside the column; table and
`pre` scroll in their own boxes.

**Scroll-spy.** Traced at 300px increments over the full 41-minute article: 26
samples, **24 correct**, 2 lagging one section at the moment a new heading
crosses the detection band, 3 correctly showing nothing before the first
heading. Deep-linking to `#s12-…` highlights the right entry on load.

**Interaction states.** Hover measured before/after on cards, rows, chips,
footer links and pagination: colour and background shifts only, **zero
geometry change** — no transform, no scale, no box-shadow anywhere. Focus ring
is `2px solid` at `3px` offset, distinct from hover, and **no clipping
ancestor** — nothing with non-visible overflow sits between a card link and the
page. Mobile ToC `<details>` opens and closes on Enter with a visible ring on
the summary. Under `prefers-reduced-motion: reduce`, 0 of 21 sampled
interactive elements retained a transition and `scroll-behavior` computes to
`auto`.

**Forms.** Newsletter with an invalid address sets `aria-invalid="true"`,
`aria-describedby="newsletter-error"`, and a `role="alert"` message in
`--danger` with the input border matching; a valid address reaches a
`role="status"` confirmation. The comment form submitted empty returns
«نام را وارد کنید» as a `role="alert"`; submitted valid it reaches
«دیدگاه شما ثبت شد. پس از بررسی و تأیید نمایش داده می‌شود» — the pending
message appears as intended.

**Theme switching at runtime.** Switched `v1 → v2-dark → v2-light → v1 →
v2-light` on a live page. The focus ring tracks every switch, including
switching back:

| theme | `--focus-ring` | live `outline-color` |
|---|---|---|
| v1 | `#4d9afe` | `rgb(77, 154, 254)` |
| v2-dark | `#4d9afe` | `rgb(77, 154, 254)` |
| v2-light | `#1a5fbf` | `rgb(26, 95, 191)` |

Chip borders use `--border-interactive` in all three. Nothing cached a theme
value. The comment error in the light theme computes to `rgb(168, 24, 15)` on
`rgb(242, 244, 247)` — **6.80:1**, matching the documented value for `--danger`
on `surface-raised` (7.49:1 on `--surface`).

**No regressions.** Full re-sweep after every change: 14 routes × 3 viewports ×
3 themes = **126 combinations, zero findings** — no horizontal overflow, exactly
one `<h1>` per page, no heading-level skips, no justified text, no italics.
`tsc --noEmit`, `next build` and `eslint .` all clean.

**Breadcrumb clamping — a correction to my own first reading.** The long title
looked like it wrapped to two lines in a screenshot. Measured: the crumb `span`
is `overflow: hidden`, `-webkit-line-clamp: 1`, height 20px against a 20px line
box — **one line**. What wraps is the `<ol>`, which is correct behaviour. No
defect.

## The four known items

**1. `CLAUDE.md` is stale, not the code — confirmed.** Already actioned in the
previous commit; `changelog.md` carries the decision that `اخبار` is a real
content type.

**2. `NewsArticle` — already fixed.** Implemented in the previous commit, before
this pass. `articleJsonLd` emits `NewsArticle` when `contentType.slug ===
'news'` and `Article` otherwise; a `news` fixture was added because the mock had
none, which is why the gap survived. Re-verified this pass.

**3. ESLint — confirmed and fixed.** See above.

**4. Bidi — the correction is right, but `dir="auto"` is the wrong remedy.**

Agreed that bracket pairing is UAX#9 (BD16), not a Chromium behaviour, so it is
portable. But `dir="auto"` should **not** be adopted. It sets direction from the
first strong character, which for a Persian-language magazine is a coin flip on
the article's opening word. Measured, comparing RTL base against `dir="auto"`
on the same strings (visual order read left-to-right):

| title | `dir="auto"` resolves | vs RTL base |
|---|---|---|
| «نات کوین (Notcoin) چیست؟» | rtl | identical |
| «شاخص دلار (DXY) و بازارهای نوظهور» | rtl | identical |
| «نسبت P/E چیست؟» | rtl | identical |
| «راهنمای Notcoin:» | rtl | identical |
| «بیت‌کوین، اتریوم و Solana — مقایسه» | rtl | identical |
| «تحلیل تکنیکال (Technical Analysis) چیست؟ …» | rtl | identical |
| **«Notcoin چیست؟»** | **ltr** | **differs — worse** |
| **«DXY و اثر آن بر طلا»** | **ltr** | **differs — worse** |

So `dir="auto"` is a no-op on six of eight and a regression on the two that
begin with a Latin ticker — precisely the realistic Mag headline
(«DXY و اثر آن بر طلا»). It flips a Persian sentence to LTR base and strands
the trailing «؟» on the wrong side.

Recommendation: leave titles to the paragraph direction. The guarantee really
is the engine's, but the engine is implementing a standard, and the proposed
alternative makes the common case worse to make an already-correct case
explicit. If a specific title is ever seen to break, isolate that fragment at
the source rather than changing base direction for all of them.

## Note — not changed

**Reading-time label is inconsistent.** `formatReadingTime()` produces
«۹ دقیقه», and every surface uses it — except `FeaturedArticle`, which appends
a word: «۳ دقیقه مطالعه». One fact, two labels. Copy, so not changed
unilaterally; pick one.

**The reading-time range reads fine.** Across the archive the values run
۳ · ۶ · ۷ · ۸ · ۹ · ۱۰ · ۱۱ دقیقه, and the long fixture adds ۴۱. A 3-minute news
item next to a 41-minute guide reads as informative, not as noise — the numbers
are doing exactly the job of setting expectation. No change needed.

**The mock's market counts are decorative.** `MARKETS[].count` sums to 14 while
`SUMMARIES` holds 7 articles, so the Topics list on the index shows numbers that
don't match its own fixtures. Pre-existing and cosmetic in the mock only — the
real counts come from WordPress — but it means the Topics counts can't be
trusted while developing.

**Buttons have no pressed state.** Measured `:active` on the newsletter submit:
no property changes on mouse-down. Hover and disabled are both handled. Minor,
but a pressed state is the feedback that a tap registered on touch.

**The top-left quadrant of the article page is empty.** The hero sits inside the
700px prose column, so at 1280px roughly 380×490px of the inline-end column is
blank above where the ToC begins. Deliberate consequence of the current
structure, not a bug — but it is the largest expanse of dead space in the
product, and it is where a ToC that started level with the hero would go.

**A 24-item flat ToC is at the edge of scannable.** It works, and the internal
scroll is the right call over an uncapped list. But scrolling a table of
contents defeats part of its purpose — seeing the shape of the article at a
glance. Worth revisiting when a real 41-minute article exists to look at;
grouping is not obviously the answer, since the ToC is deliberately H2-only.

**The archive's new empty state is not directly exercisable.** All four content
types have articles in the mock, so the `page 1 + zero items` branch can't be
reached locally. It mirrors the market and author paths, which are verified.

## Judgement

**Opening `/mag` cold, the eye lands on the hero artwork, then the headline
beside it.** That is the intended hierarchy and it works: masthead, one lead,
then «تازه‌ترین‌ها» and «موضوع‌ها» as two clearly-weighted columns. The one thing
that undercuts it is what the lead *is* — see below.

**The lead slot is the real product question this pass surfaced.** The index
leads with the newest article. With an RSS automation filing roughly two
«اخبار» items a day, the newest article will almost always be a short
translated news item — in this pass the hero became a 3-minute Fed headline.
A magazine whose identity is analysis and education would then never show
analysis or education in its lead slot. Recommend the lead be the newest
*substantive* piece — newest excluding `news`, or an editor-picked lead — and
news live in the list. This is a product decision, not a bug, so it is flagged
rather than changed.

**32 articles is restrained, not sparse.** The text-forward list reads as
editorial. Showing artwork once and titles everywhere else is the right call and
the pages don't feel thin — the section rules group without boxing, and the
whitespace reads as confidence rather than absence. The one place it tips
towards unfinished is the hover affordance on archive rows: the entire row is
clickable but only the title changes colour, which is subtle for a target that
large.

**Reading-time-first in the meta row is useful.** «۹ دقیقه · گزارش · ۲۷ مرداد
۱۴۰۵» leads with the reader's actual question — is this a two-minute skim or a
commitment — before genre and date. It also reads naturally in Persian. Keep.

**The article page does feel like a place to read 41 minutes of Persian.** 700px
at 18px/1.9 is a comfortable measure, the ToC is genuinely navigable, the
scroll-spy tracks, and there is no chrome competing for attention. The two
things standing between it and excellent are the dead top-left quadrant and the
fact that the ToC starts below the fold on a long hero.

**The three themes feel like one product.** Same structure, same spacing, same
weights; only surface and text roles move. v2-light is no longer the weak one —
the focus ring fix landed and the danger colour holds 6.80:1 on raised surface.
v1 navy reads as the most distinctive of the three.

**If I had one change: make the lead slot exclude `news`.** Everything else here
is a defect with a fix or a note with a trade-off. That one is the difference
between a magazine that looks like what it is and one whose front page is
permanently occupied by wire copy — and it gets worse every day the automation
runs, not better.
